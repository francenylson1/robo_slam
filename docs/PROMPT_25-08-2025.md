#### V4 - Controle Diferenciado Ida vs Retorno
- **Inovação:** Parâmetros diferenciados baseados em `is_returning_to_base`
- Angular speed: `0.4` (retorno) vs `0.7` (ida)

#### V5 - Tolerância Ultra-Expandida para Retorno
- Tolerância de ângulo: `45.0°` (retorno) vs `20.0°` (ida)
- **Resultado:** Ainda persistiram loops de 360°

#### V6 - Solução Genial: Retorno Direto
- **Conceito:** Bypass total do PathFinder complexo no retorno
- Método `_return_to_base_direct()` usando coordenadas conhecidas
- Navegação direta: `[current_position, ROBOT_INITIAL_POSITION]`

#### V7 - Navegação Revolucionária

- Estado forçado: `"NAVIGATING_TO_DESTINATION"` (pula orientação)

#### V8 - Correção do Movimento Angular (25/08/2025)
- **Descoberta:** Problema não estava no `_orient_towards_target()`, mas no `_move_towards_target()`
- **Correção:** Fator angular diferenciado:
  - IDA: `1.8` (mantém precisão)

## 🔍 ANÁLISE TÉCNICA DO PROBLEMA

### Arquivos Principais Envolvidos:
- **`src/core/robot_navigator.py`**: Lógica de navegação e retorno
- **`src/interfaces/main_window.py`**: Interface que chama `navigate_to_and_return()`
- **`src/core/config.py`**: Parâmetros como `ROBOT_INITIAL_POSITION = (5.7, 11.5)` e `ROBOT_INITIAL_ANGLE = 270`

### Estados da Navegação:
1. `"IDLE"` → `"NAVIGATING_TO_DESTINATION"` (ida direta)
2. `"PAUSED_AT_DESTINATION"` (chegada ao POI)
3. `"RETURNING_TO_BASE"` ou orientação ← **AQUI ACONTECE O LOOP**

### Hipóteses Atuais:
1. **Conflito de Estados:** Sistema pode estar alternando entre estados de navegação
2. **Cálculo de Ângulo:** Problema na determinação do ângulo para retorno à base
3. **Condições de Transição:** Lógica de transição entre estados pode ter falha
4. **Tolerâncias Insuficientes:** Mesmo com 45°, ainda pode precisar de mais tolerância
