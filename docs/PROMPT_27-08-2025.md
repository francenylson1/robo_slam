## 📈 EVOLUÇÃO DAS CORREÇÕES IMPLEMENTADAS

### Correções Aplicadas na Jornada:

#### V1 - Correção Inicial da Orientação (22/08/2025)
- **Problema:** Robô com direção inicial instável causando navegação diagonal
- **Solução:** Suavização do método `_orient_towards_target()`
- **Resultado:** Melhorou estabilidade inicial, mas surgiram loops no retorno

#### V2-V3 - Refinamentos de Parâmetros 
- Reduziu fator angular de `5.0` para `0.7`
- Reduziu `MIN_TURN_TPS` de `20.0` para `5.0`
- Expandiu tolerância de ângulo de `5.0°` para `20.0°`

#### V4 - Controle Diferenciado Ida vs Retorno
- **Inovação:** Parâmetros diferenciados baseados em `is_returning_to_base`
- Angular speed: `0.4` (retorno) vs `0.7` (ida)
- MIN_TURN_TPS: `3.0` (retorno) vs `5.0` (ida)

#### V5 - Tolerância Ultra-Expandida para Retorno
- Tolerância de ângulo: `45.0°` (retorno) vs `20.0°` (ida)
- **Resultado:** Ainda persistiram loops de 360°

#### V6 - Solução Genial: Retorno Direto
- **Conceito:** Bypass total do PathFinder complexo no retorno
- Método `_return_to_base_direct()` usando coordenadas conhecidas
- Navegação direta: `[current_position, ROBOT_INITIAL_POSITION]`

#### V7 - Navegação Revolucionária
- **Mudança Radical:** `navigate_to_and_return()` usa navegação direta (2 pontos) para ida
- Eliminou PathFinder complexo: `[current_position, destination]`
- Estado forçado: `"NAVIGATING_TO_DESTINATION"` (pula orientação)

#### V8 - Correção do Movimento Angular (25/08/2025)
- **Descoberta:** Problema não estava no `_orient_towards_target()`, mas no `_move_towards_target()`
- **Correção:** Fator angular diferenciado:
  - IDA: `1.8` (mantém precisão)
  - RETORNO: `0.2` (11x mais suave)
